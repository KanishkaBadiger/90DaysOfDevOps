# Day 04 – Linux Practice: Processes and Services

## 1. Process Checks

A process is a running instance of a program. Linux assigns a unique Process ID (PID) to each process.

### 1.1 `ps`

```bash
ps
```

`ps` displays information about processes currently associated with the current terminal/session.

I practiced this command to understand how Linux keeps track of running processes.

---

### 1.2 `ps -a`

```bash
ps -a
```

This displays processes associated with terminals, including processes from other sessions.

I practiced this command to understand how Linux keeps track of running processes.

---

### 1.3 `top`

```bash
top
```

`top` displays running processes in real time.

It provides information such as:

- Process ID (PID)
- CPU usage
- Memory usage
- Process owner
- Running processes

It is useful for troubleshooting high CPU or memory usage.

For example, if a server becomes slow, I can use `top` to identify processes consuming a large amount of CPU or memory.

---

### 1.4 `free -h`

```bash
free -h
```

The `free` command displays memory usage.

The `-h` option displays the values in a human-readable format.

It helps me check:

- Total memory
- Used memory
- Available memory
- Swap memory

---

## 2. Service Checks

A Linux service is a background program that performs a particular function.

Examples include:

- SSH
- MySQL
- MongoDB
- Docker

I have practiced services such as MySQL and MongoDB while working with Ubuntu.

---

### 2.1 Check a service using `systemctl`

```bash
sudo systemctl status <service>
```

This command displays the current status of a service.

It can show whether the service is:

- Running
- Stopped
- Failed
- Enabled/disabled

For example, to check SSH:

```bash
sudo systemctl status ssh
```

---

### 2.2 List running services

```bash
systemctl list-units --type=service --state=running
```

This command lists services that are currently running.

It is useful when I want to get an overview of active services on a Linux server.

---

### 2.3 Start a service

```bash
sudo systemctl start <service>
```

Starts a stopped service.

Example:

```bash
sudo systemctl start ssh
```

---

### 2.4 Stop a service

```bash
sudo systemctl stop <service>
```

Stops a running service.

---

### 2.5 Restart a service

```bash
sudo systemctl restart <service>
```

Restarts a service.

This can be useful after making configuration changes or when a service is not behaving correctly.

## 5. Log Checks

Logs are very important for troubleshooting Linux services.

They help us understand:

- What happened
- When it happened
- Whether a service failed
- Why a service failed
- What errors occurred

---

### 5.1 `journalctl`

```bash
sudo journalctl -u <service>
```

`journalctl` is used to view logs collected by `systemd`.

The `-u` option allows us to view logs for a particular service.

For example:

```bash
sudo journalctl -u ssh
```

This displays logs related to the SSH service.

---

### 5.2 View the latest service logs

```bash
sudo journalctl -u <service> -n 20
```

The `-n 20` option displays the latest 20 log entries.

Example:

```bash
sudo journalctl -u ssh -n 20
```

This is useful when I want to quickly check recent events instead of reading the complete log history.

---

### 5.3 View logs from a specific time

```bash
sudo journalctl -u <service> --since "1 hour ago"
```

This displays logs generated by the service during the last hour.

This can be useful when troubleshooting a problem that happened recently.

---

### 5.4 `tail`

```bash
tail -n 50 <log-file>
```

The `tail` command displays the last part of a file.

The `-n 50` option displays the last 50 lines.

It is commonly useful for checking the latest entries in application or system log files.

## 7. Mini Troubleshooting Flow

A basic Linux troubleshooting process I learned is:

### Step 1 – Check system resources

First, check CPU and memory usage.

```bash
top
```

```bash
free -h
```

If the server is running out of disk space:

```bash
df -h
```

---

### Step 2 – Check running processes

Use `ps` to inspect running processes.

```bash
ps
```

For more information:

```bash
ps -a
```

If I need real-time information:

```bash
top
```

---

### Step 3 – Check the service

If an application or service is not working, check its status.

```bash
sudo systemctl status <service>
```

For example:

```bash
sudo systemctl status ssh
```

---

### Step 4 – Check service logs

If the service has failed or is behaving unexpectedly, check its logs.

```bash
sudo journalctl -u <service> -n 20
```

For example:

```bash
sudo journalctl -u ssh -n 20
```

---

### Step 5 – Restart the service if required

If the service is stopped or has encountered an issue:

```bash
sudo systemctl restart <service>
```

---

### Step 6 – Check the service again

After restarting, verify its status:

```bash
sudo systemctl status <service>
```

---

## 8. Practical Troubleshooting Example

### Problem

Suppose an application running on a Linux server is not responding.

### My troubleshooting approach

**1. Check system resources**

```bash
top
```

```bash
free -h
```

**2. Check whether the required process is running**

```bash
ps
```

**3. Check the service**

```bash
sudo systemctl status <service>
```

**4. Check recent logs**

```bash
sudo journalctl -u <service> -n 20
```

**5. Restart the service if necessary**

```bash
sudo systemctl restart <service>
```

**6. Verify again**

```bash
sudo systemctl status <service>
```

This gives me a simple and systematic way to troubleshoot instead of randomly running commands.

## Key Learnings

- A process is a running instance of a program.
- Every process has a Process ID (PID).
- `ps` is useful for checking processes.
- `top` is useful for real-time process and resource monitoring.
- `systemd` manages many services on modern Linux systems.
- `systemctl` is used to inspect and manage systemd services.
- `journalctl` is useful for checking service logs.
- `tail` can be used to inspect the latest lines of log files.
- Services can be started, stopped, restarted and inspected.
- Checking processes, services, resources and logs is an important part of Linux troubleshooting.
